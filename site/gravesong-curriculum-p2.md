04b_GRAVESONG_CURRICULUM v1 - part 2 of 2: Novice -> Beginner exam sets. Blueprint per 04_curriculum section D: 11 items (8 theory, 1 short code, 1 output prediction, 1 flawed review with at least 3 issues). Keys are for the examiner; grade the idea, not the wording. Free-form answers, one item at a time, in character. Simulated output is labelled.

### Gravesong Novice -> Beginner (Sable)

Set A
1. (u1) A user says "the website is slow". Name the layer you would check for each: a duplex mismatch on the switch, a DNS server timing out, a TLS handshake failing, a 502 from the proxy. - Key: link (L1/L2); application-layer service DNS (L7, carried over UDP/TCP); TLS (session/presentation in OSI, between transport and application in TCP/IP); HTTP/application (proxy cannot reach upstream).
2. (u2) What is 10.20.0.0/22: first and last usable address, and how many hosts? Is it reachable from the internet? - Key: 10.20.0.1 - 10.20.3.254, 1022 hosts; private (RFC 1918), not routable on the internet unless NAT or a port forward exposes something.
3. (u3) A record vs CNAME vs MX. You changed an A record an hour ago and some users still reach the old server. Why, and what should you have done first? - Key: name to IPv4 / alias to another name / mail exchanger; caching by TTL; lower the TTL well before the change.
4. (u4) What do 301, 403, 404, 502 and 504 mean, and which two point at the proxy's upstream? - Key: moved permanently, forbidden, not found, bad gateway, gateway timeout; 502 and 504.
5. (u5) A certificate for www.example.org is served on example.org and the browser warns. Why? Name two other common causes of certificate errors. - Key: name not in the SAN; expired, incomplete chain (missing intermediate), self-signed or untrusted CA, clock wrong.
6. (u7) Why does an app behind nginx log every client IP as 127.0.0.1, and what fixes it? Why must the app not trust X-Forwarded-For from anyone? - Key: the proxy is the client; set X-Forwarded-For (or X-Real-IP) in nginx and read it in the app only from trusted proxies; clients can forge the header.
7. (u8, u9) A server needs SSH from the office only and HTTPS from anyone. Describe the inbound firewall rules and the default. What two SSH settings would you change? - Key: default deny inbound; allow 443 from any; allow 22 from the office range; allow established/related; PasswordAuthentication no, PermitRootLogin no (keys only).
8. (u10, u11) Name the four golden signals. Your SLO is 99.9% of requests successful per 30 days: what is the error budget, and what happens when it is spent? - Key: latency, traffic, errors, saturation; 0.1% of requests (about 43 minutes of full outage in 30 days); freeze risky releases and spend effort on reliability until it recovers.
9. Code (u7): an nginx server block listening on 80 for shop.example that passes everything to an app on 127.0.0.1:8000 and forwards the client address. - Key: server { listen 80; server_name shop.example; location / { proxy_pass http://127.0.0.1:8000; proxy_set_header Host $host; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; } }
10. Predict (u6) (simulated): ss -tulpn shows "tcp LISTEN 0.0.0.0:5432 postgres" and "tcp LISTEN 127.0.0.1:6379 redis". From another machine on the LAN, which of nc -zv host 5432 and nc -zv host 6379 succeeds? - Key: 5432 succeeds (all interfaces) unless a firewall blocks it; 6379 fails (loopback only).
11. Review (u2, u7, u8, u12) - find at least 3 issues in this oracle-written fix for "the site is down": "Run sudo ufw disable to rule out the firewall. Set proxy_pass to the app's public IP. Add curl -k to the health check because the certificate is failing. Open port 8000 to 0.0.0.0/0 so the load balancer can reach it." - Key: disabling the firewall widens exposure and may never be re-enabled (test the specific rule instead); proxying to a public IP sends traffic out and back and exposes the app (use the private or loopback address); -k hides the real certificate fault (fix the chain or expiry); open the port only to the load balancer's address range.

Set B
1. (u1) What is encapsulation? A web request leaves your laptop: list the headers wrapped around it, from inside out. - Key: each layer adds its own header around the layer above; HTTP inside TCP inside IP inside Ethernet (or Wi-Fi) frame.
2. (u2) What does NAT do at a home router? Why can't the internet reach your laptop's port 22 by default, and what would change that? - Key: rewrites private source addresses to the public one and tracks connections; no inbound mapping exists; a port forward (or UPnP, or a tunnel).
3. (u3) Walk the resolution of www.example.org from a laptop with an empty cache. What does a dangling CNAME risk? - Key: stub resolver to recursive resolver, root, .org TLD, example.org authoritative, answer cached by TTL; a CNAME pointing to a deleted cloud resource can be claimed by someone else (subdomain takeover).
4. (u4) curl -I https://site returns "Server: nginx/1.18.0 (Ubuntu)" and no Strict-Transport-Security. Name the two concerns. - Key: version disclosure helps attackers match CVEs (server_tokens off); no HSTS lets a first visit be downgraded.
5. (u5) How does ACME prove you control a domain? What happens operationally if renewal silently fails? - Key: HTTP-01 (a token served on port 80) or DNS-01 (a TXT record); the certificate expires and clients refuse to connect; monitor expiry and alert well before.
6. (u6, u9) TCP vs UDP for a heartbeat sent every second: which, and why? Why can't you carry it through an ordinary SSH local forward? - Key: UDP: a lost beat is just a missed beat, no connection state; SSH port forwarding carries TCP only; use WireGuard or a LAN.
7. (u9) Explain ssh -L 8080:localhost:5432 db-host. Who can reach the database through it, and what is the risk if it binds to 0.0.0.0? - Key: local port 8080 forwards over SSH to db-host's own localhost:5432; by default only the local machine; on 0.0.0.0 anyone on the laptop's network reaches the database through you.
8. (u11, u12) Behavioural: a colleague wants to write the postmortem naming who pushed the bad config. What do you say, and what goes into a good postmortem? - Key: blameless: focus on the system that let it happen; timeline, impact, detection, root and contributing causes, what went well, action items with owners and dates.
9. Code (u10): a PromQL expression for the per-second rate of HTTP 5xx responses over 5 minutes, from a counter http_requests_total with a status label. - Key: sum(rate(http_requests_total{status=~"5.."}[5m])) (sum optional).
10. Predict (u3) (simulated): dig shop.example +short returns "shop.lb.cloudhost.net." then "203.0.113.20". What are the two lines, and which record does each come from? - Key: a CNAME target, then the A record of that target.
11. Review (u5, u7, u10) - find at least 3 issues in this oracle-written nginx and monitoring note: "listen 443 ssl; ssl_certificate /etc/nginx/key.pem with mode 644; proxy_pass http://app; with no upstream defined; expose /metrics on the public server block so Grafana Cloud can scrape it; log full request headers for debugging." - Key: private key world-readable (600, owned by root) and file naming suggests key and certificate confused (needs ssl_certificate and ssl_certificate_key); an upstream named app must be defined or it fails nginx -t; public /metrics leaks internals (restrict by IP, auth, or a separate internal listener); full headers log cookies and Authorization tokens.
END OF GRAVESONG CURRICULUM v1
